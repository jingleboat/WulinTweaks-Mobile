# 剧情条件放宽 / 分支展开 —— 能力边界与「完整实现」代价评估

> 决策文档（供讨论）
> 日期：2026-11-03　当前版本：Android v171 / PC 1.11.56
> 结论提要：**当前设计满足需求 1 的约 91%，需求 2 只在「串行链」图上成立；要做到任意多角色依次播放，必须换成运行期调度，代价显著。**

---

## 一、需求的形式化

用户目标（原话归纳）：

1. **P1 可达**：角色不在队，也能触发他「在队时」的相关剧情；
2. **P2 顺序**：如果图里有多个角色相关剧情，**每一个都要被判定**（而不是只播一个）；
3. **P3 唯一**：每段内容只播一次，不重复、不循环。

三者同时成立，才算「完整实现」。

---

## 二、当前实现（放宽 + 展平）的能力

### 2.1 两个功能各自负责什么

| 功能 | 作用 | 能保证的性质 |
|---|---|---|
| **剧情条件放宽** | 把「需要伙伴」条件判真（跳过该条件） | P1（进得去） |
| **剧情分支展开（区域法）** | 把在队侧内容的出口改接到不在队门，两道门都强制放行 | P1 + P2 + P3（仅限串行结构） |

**关键**：放宽只负责「判真」，不负责「接下去」；不接，就停在那一支。

### 2.2 全库普查数据（1804 张剧情图，689 个「需要伙伴」互补门对）

| 类别 | 对数 | 占比 | P1 | P2 | P3 |
|---|---|---|---|---|---|
| **A. region>0**（在队侧内容可达独占） | **577** | 83.7% | ✅ | ✅ | ✅ |
| **B. region=0 但「入口独占」**（如 `R10049-2-1` 的四对） | **51** | 7.4% | ✅ | ⚠️ | ❌ 可能成环 |
| **C. 两侧真正共享** | **61** | 8.9% | 仅靠放宽 | ❌ | ❌ |

- A 类：现有算法已验证可用（洛千雪等 5 人依次播即此类）；
- B 类：能被放宽「进得去」，但没有可靠的出路，静态改线接回去**可能形成回路**；
- C 类：两侧可达集完全重合，静态改线无从下手。

**覆盖结论：P1 ≈ 628/689 = 91.1%；P2/P3 仅对 A 类（83.7%）成立。**

### 2.3 典型反例：`R10049-2-1`（李乐雅/付瑶琴/顾倾城/鱼薇儿）

```
pid=10061：N0 出边 → _4_2；_4_2 从 N1 侧也可达 → region = 0
pid=10075：同上（_4_3）
pid=10052、10098：同类
可达集：N0 与 N1 各 33 个节点，完全相同
```

**这张图的写法是「四道门通往同一张网，靠先命中谁实现互斥」**，天然不支持「依次播放」。目前只靠原版条件决定播谁（鱼薇儿在队 → 播她）。

## 三、数学层面的结论

### 3.1 充分条件（A 类为什么可行）

```
若 Reach(N0_i) \ Reach(N1_i) 非空，
且各 N0_i 的独占区域两两不交、N1_i 不回到任何 N0_j 的内容
（即门对之间构成「串行偏序」）
则：把每个独占区域的出口改指 N1，可保证 P1 ∧ P2 ∧ P3
```

这正是 `R10049-2` 的情形。

### 3.2 不可能性（B/C 类为什么静态做不到）

```
P2 要求：存在一条依次经过 A、B、C、D 四段内容的路径
P3 要求：每段恰好一次
```

在「共享可达」的图上，这等价于要求一条**覆盖指定节点的简单路径**。而静态改线只能改变边的指向、**不能删除共享边**：

- 把 A 的出口指回 N1，若 N1 的子树仍包含 A 的内容（B/C 类正是如此），则形成回路 → P3 破坏；
- 不指回 N1，则 A 播完没有出路 → P2 破坏。

**结论：对 B/C 类（合计 112 对，16.3%），任何纯静态改线都无法同时满足 P2 与 P3。** 这不是实现问题，是结构决定的。

### 3.3 完整实现的必要条件

必须引入**运行期状态**：

```
每个「播放实例」维护一个 "已播内容集合"
门放行时：目标内容已在集合中 → 跳过（改走 N1）
          否则 → 播放并记入集合
全部播过 → 走 N1 收尾
```

性质上从「静态改写图」变成「运行时调度」，这是另一套机制。

## 四、工程层面的缺口

| # | 缺口 | 影响 | 现状 |
|---|---|---|---|
| 1 | **引擎选边语义未验证**（“按连接顺序取第一个为真”） | 所有 P2 推理的地基 | 从未验证 |
| 2 | **无运行期「已播」集合** | B 类可能循环、重复播 | 不存在 |
| 3 | **放宽与展平作用域冲突** | 放宽判真会抢占别的角色（鱼薇儿事件即此） | v171 已部分收敛 |
| 4 | **节点类型覆盖不全** | 独立剧情节点（`StoryOpenNode`）无日志、未验证；嵌套/跨端口门对不识别 | 日志盲区 |
| 5 | **播放完成回调缺失** | 运行期调度需要「这段播完了」的信号 | 无可靠钩子 |

## 五、两条可选路线与代价

### 路线 S：维持静态（现状 + 小幅补齐）

| 项 | 内容 |
|---|---|
| 做法 | 保留 region 法；对 B 类加「入口独占 + 链式接续」，并加环检测，失败则跳过 |
| 覆盖 | P1 → 91%，P2/P3 → 仅 A 类（+B 类中不成环的部分，预估不超过一半） |
| 工作量 | **小**（改动集中在一个判据 + 复用现成事务/环检测） |
| 风险 | 中：B 类若成环会卡剧情，需要严格的回滚与跳过 |
| 验收 | 离线模拟 51 对，逐对判定「是否成环」；成环者跳过 |

### 路线 R：运行期调度（完整实现）

| 项 | 内容 |
|---|---|
| 做法 | 展平只强制放行不换线；新增「已播集合」，门放行后由调度器决定下一跳 |
| 覆盖 | P1 + P2 + P3 可完整满足（含 B/C 类） |
| 工作量 | **大**：需要播放实例、已播集合、播完回调、跳转决策、回环保护，且两端各实现一遍 |
| 前置 | 必须先解决缺口 #1（引擎选边语义）与 #5（播完回调）；#4 的 `StoryOpenNode` 钩子历史上曾导致闪退（v143/v151），需另找安全注入点 |
| 风险 | 高：调度器一旦判错，表现为剧情乱序、重复、卡死；回归面覆盖 692 张图 |
| 验收 | 需要逐图对比「原版 vs 调度」的播放序列，工作量与测试成本都远高于路线 S |

### 路线 N：明确边界（不做）

| 项 | 内容 |
|---|---|
| 做法 | 承认 B/C 类「只能播一位」，在文档与配置里写清；不做额外改动 |
| 覆盖 | P1 ≈ 91%，P2/P3 仅 A 类 |
| 工作量 | 无 |
| 风险 | 无 |

## 六、代价与收益的量化视角

| 维度 | 路线 S | 路线 R |
|---|---|---|
| 能多覆盖的门对 | B 类 51 对中的一部分（取决于成环比例，**尚未测量**） | 全部 112 对（B+C） |
| 涉及剧情图 | 需离线统计（预计几十张） | 692 张全部暴露在风险下 |
| 实现工作量 | 1 个判据 + 环检测（小） | 播放实例 + 调度器 + 回调（大，两端各一次） |
| 验证成本 | 离线模拟为主 | 需要大量实机回归 |
| 失败表现 | 该图保持原版（可回滚） | 剧情乱序/重复/卡死（影响面大） |

**关键判断点**：B 类 51 对里到底有多少能在链式接续下**不成环**——这个数字决定路线 S 的性价比。可以离线测，成本很低。

## 七、待补的一个关键数据（成本极低）

```
对 51 个 B 类门对逐一做「链式接续模拟」：
    若接续后出现环 → 该对不可静态展开
    否则 → 可展开
输出：可展开数 / 总数
```

这个数字出来之后，「路线 S 值不值」就有客观依据，不必凭感觉。

---

## 八、建议的决策顺序

1. **先补第七节那个统计**（离线，几十分钟内可完成）；
2. 若可展开比例高（例如 >60%）→ 走 **路线 S**，一次性拿到大部分收益，风险可控；
3. 若比例低（<30%）→ B 类基本无法静态解决，此时只有两个选择：
   - 接受 **路线 N**（明确边界，只保证 A 类）；
   - 或投入 **路线 R**（完整实现，代价与风险显著上升）。
4. 无论走哪条，都应先解决缺口 #1（引擎选边语义），因为它是所有 P2 结论的前提。

---

## 九、需要讨论/拍板的问题

1. **需求优先级**：P1 与 P2 哪个是硬要求？若“多角色依次播”只是锦上添花，路线 N/S 即可。
2. **可接受的失败模式**：宁可不展开（保持原版）还是宁可尝试（可能卡剧情）？
3. **是否愿意为 B/C 类（16.3% 的门对）承担运行期调度的复杂度与回归成本**？
4. **`StoryOpenNode` 钩子**：历史上导致过闪退，是否允许再投入时间寻找安全注入点？

## 十、附录：已确认的事实与已辟除的误判

**已确认（有存档/日志/资产证据）**

- `R10049-2` 的 12 对全部 region=1，展平可用；`-2-1` 的 4 对 region=0。
- 存入存档的 `R10049-2` 已通过 SaveID = [22,23,24,26,93,111,112]，**不含 27、28**；`_3_0` 分支由「判断存在标记」决定 → 沈无欺（10054）支线**从未走过**，属进度前置未满足，与 mod 无关。
- 鱼薇儿事件：v171 起对「未被展平接管」的门对不再放宽，日志显示 10061/10075/10052 依次 `VANILLA_FAIL`、10098 `VANILLA → 通过`。

**已辟除的误判（避免重复踩坑）**

- ❌「12 对门全是幽灵配对、应 0 对」——起因是 YAML 解析器混用 InPort/OutPort 连线，结论作废。
- ❌「引擎一定先问 Negate=1」——未经证实。
- ❌「展平配对应该 0 对」——运行时配对确实是真兄弟门对。
- ❌「我的判据是完备的」——普查证明覆盖率 91.9%，存在结构性缺口（B/C 类 112 对）。

## 十一、追加（2026-11-03 晚）：链式接续已实现并验证通过

### 11.1 关键转折

此前判定「B/C 类静态不可解」，是**针对“接回本对 N1”这一种改法**。实测表明另有一种改法是可行的：

`
把「角色 i 的内容末端」接到「角色 i+1 的**在队门**」（不是接回自己的 N1）
`

这样绕开了 N1 子树，因此**不会回到原处成环**。这与 2026-10-22 的 PC 手写补丁同型。

### 11.2 离线校验（41 张 B/C 图）

| 结果 | 图数 | 说明 |
|---|---|---|
| 只有 1 个 B/C 对 | 29 | 无需串接（谈不上“依次”） |
| **可自动生成并校验通过** | **4** | M5061-5(6 人)、R10005-5、R10049-2-1(4 人)、R10098-1 |
| 需人工定序/结构特殊 | 6 | M2155-6、Role5-15-2、R10007-4、Role5-10、M5061-3、R10039-6、School-2030-2 |

R10049-2-1 校验：环数 16 → 15（无新增环），四段内容与四道门均可达。

### 11.3 实机验证（手机 v172/v173）

`
[flat] 图 R10049-2-1 链式接续：改线 3 条（按名单 4 个角色顺序）
[gate] pid=10061 侧=在队 forced=Y 源=FLATTENED → 通过   李乐雅
[gate] pid=10075 侧=在队 forced=Y 源=FLATTENED → 通过   付瑶琴
[gate] pid=10052 侧=在队 forced=Y 源=FLATTENED → 通过   顾倾城
[gate] pid=10098 侧=在队 forced=Y 源=FLATTENED → 通过   鱼薇儿
`

用户确认：**四段剧情依次全部播放**。修复前只有 pid=10061 一道门通过。

### 11.4 已落地的实现

| 端 | 版本 | 内容 |
|---|---|---|
| Android | v173 | k_chains[] 静态表（4 张图）+ lat_apply_chain() |
| PC | 1.11.57 | 同表 + ApplyChain()（改动仅在有名单的图上生效） |

实现要点：
- 改的是「添加标记/追加简介」这类单出口副作用节点的**出口**，因此标记仍会写入；
- 被接管的对 Skip=true，不再走 region 法；
- 两端表内容完全一致；
- 失败可整图回滚（复用既有事务）。

### 11.5 修正后的能力结论

| 类别 | 对数 | 静态可实现 | 手段 |
|---|---|---|---|
| A：region>0 | 577 | ✅ | region 法（已有） |
| B/C：region=0 | 78（B 45 / C 33） | **部分** ✅ | 链式接续表（已覆盖 4 张图，含多角色场景） |
| 剩余 | 6 张图 | ❓ 待人工定序 | 逐张离线分析 |

**结论更新：不再需要「运行期调度」来满足多角色依次播放；名单 + 链式接续表即可，代价约 1 人日，风险局限在 4~10 张图。**
